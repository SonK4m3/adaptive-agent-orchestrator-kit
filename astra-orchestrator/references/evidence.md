# Source ledger — inspected 2026-10-01

These sources inform policy. They do not establish that this kit is universally best. No comparable benchmark found in this review ranks Astra/Sol/Luna across this user's tasks, deadline modes and orchestration patterns.

| Source | Evidence and limitation | Design consequence |
| --- | --- | --- |
| [SWE-agent paper, 2024 v3](https://arxiv.org/abs/2405.15793v3) | Reports pass@1 12.5% on SWE-bench and 87.7% on HumanEvalFix with its agent-computer interface. Historical models and scaffold; not a current Codex model comparison. | Tool interface and context handling matter alongside model selection. |
| [Single-agent or Multi-agent Systems? Why Not Both?, 2025](https://arxiv.org/abs/2505.18286v1) | Reports shrinking multi-agent gains as model capability improves; its hybrid approach improves accuracy by 1.1–12% and reduces deployment cost up to 20% across its evaluated applications. A preprint covering heterogeneous tasks, not a promise for coding here. | Keep L0 valid and adapt topology based on concrete need. |
| [SWE-bench leaderboard](https://www.swebench.com/) | Different splits and submitted systems are distinguished. A result is a model-plus-scaffold result on a particular dataset. | Record split, harness, attempts and setup before comparing scores. |
| [OpenAI audit of SWE-bench Verified](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/) | Reports test/specification defects and contamination concerns. Its audited subset is not a random sample of all tasks. | Keep requirement-derived and local held-out acceptance checks; do not treat leaderboard position as complete evidence. |
| [mini-SWE-agent](https://github.com/SWE-agent/mini-swe-agent) | Maintainer describes a compact agent with strong benchmark results. Repository claims are not a controlled comparison against this kit. | Do not assume a larger team or more configuration improves outcomes. |
| [OpenAI multi-agent documentation](https://developers.openai.com/api/docs/guides/responses-multi-agent) | Independent tasks can benefit; ordered dependencies, shared state and added token use limit gains. This API's schema is not automatically the desktop tool schema. | Parallelize disjoint work and verify the active runtime. |
| [Codex subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) | Describes model inheritance, custom-role precedence and reasoning tradeoffs. Account/runtime availability can differ. | Check role pins, use supported choices and retain runtime evidence. |
| [Official model guide](https://developers.openai.com/api/docs/guides/latest-model) | Describes Astra, Sol and Luna capability/cost positioning. Provider guidance is not a measured task latency guarantee. | Use capability tiers as priors; calibrate against completed work. |
| [donvito orchestrator](https://github.com/donvito/codex-astra-luna-orchestrator) | Provides root/execution/reviewer profiles and installation conventions. It is an implementation reference, not comparative efficiency evidence. | Retain clear role contracts while replacing mandatory model/count habits with task-based selection. |
| [Jev router](https://github.com/0xNatoshi/jev-codex-router) and [support matrix](https://github.com/0xNatoshi/jev-codex-router/blob/main/docs/SUPPORT.md) | Per-call model routing; full installation is macOS-specific. Historical simulated savings are not measured quality-equivalent savings for this kit. | Keep topology and model routing separate; Jev is optional and not installed here. |

Local hypotheses to test: stronger reasoning can reduce rework on difficult critical-path tasks; economical agents can reduce cost on narrow tasks; independent review can catch integration mistakes. Each can fail for a particular workload. See evaluation.md for the comparison protocol.
